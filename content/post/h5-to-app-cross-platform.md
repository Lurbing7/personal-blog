# 一个人项目从 H5 到 App：PWA、Capacitor 与 uni-app 的跨端选型

## 背景与问题

`bz-lottery` 是一个基于 Spring Boot 3 + Vue 3 的个人抽奖平台项目，定位是做成可演示、可复用、可接单改造的小型业务系统模板。产品上规划了双端 Web：`/admin` 是 PC 运营后台，`/app` 是手机用户端，共用登录入口。

手机端跑通 H5 之后，自然会问：要不要做成 App？直接上原生 iOS、Android、鸿蒙三端，意味着三套工程、三份维护成本。

## 渐进路线：先 H5，再 PWA，最后包壳

路线图定成渐进式，每一步都有可展示成果：

```text
手机 H5 → PWA → Capacitor 包 iOS / Android → 根据业务需要评估 uni-app / 鸿蒙原生
```

### 阶段一：手机 H5

`/app` 是用户参与端：活动首页、抽奖页、我的记录、我的。移动端优先，抽奖按钮、奖池、结果反馈要突出，底部 Tab 导航，交互不依赖 PC hover。

目标：浏览器可访问、视口布局正常、可登录抽奖查记录，与 PC 后台共用 API 和登录态。

选择 H5 的理由：开发最快、成本最低、适合验证业务和 UI、不涉及应用商店审核。业务没验证前，为 App 提前付出的工程成本都是浪费。

### 阶段二：PWA

PWA（Progressive Web App）是可以像 App 一样安装到手机桌面的 Web 应用。保留 Web 技术栈，不需要上架应用商店，是 H5 到 App 之间的低成本过渡形态。

可增强的能力：

- 桌面图标和全屏打开
- 静态资源缓存
- 弱网体验优化
- 基础离线提示
- 后续可探索消息提醒

PWA 的边界清楚：它仍是网页，能力受系统浏览器限制。

### 阶段三：跨端壳 App

H5 业务和交互跑通后，用跨端方案把 Web 应用包装成 App，业务代码尽量复用现有 Vue 代码，而不是重写。

## 四个候选方案的取舍

| 方案 | 适合场景 | 主要代价 |
|---|---|---|
| Capacitor | 把现有 Vue H5 包成 iOS / Android | 迁移成本相对低 |
| uni-app | H5、小程序、App、鸿蒙等多端 | 国内生态强，但要迁入 uni 体系 |
| Flutter | 体验好 | 要用 Dart 重写 UI |
| React Native | 生态成熟 | 与当前 Vue 技术栈不顺 |

四个方案放在一起，取舍的关键是：现有代码能复用多少。结合当前技术栈，优先路线是 Vue H5 → PWA → Capacitor：现有 Vue H5 可直接包装成 App，迁移成本最低，前端代码不用换体系。

uni-app 不在一开始引入：它更适合多端场景，但前端代码要改造进 uni 体系，是改造而不是包装。判断标准：后续确定要适配小程序或鸿蒙生态，再评估 uni-app。

Flutter 和 React Native 被排除：Flutter 体验好但要 Dart 重写 UI；React Native 生态成熟但与 Vue 技术栈不顺。对单人项目，"重写 UI"意味着 H5 阶段投入作废。

## 鸿蒙：分层看待

鸿蒙要分层看待，不能一刀切：

- 手机浏览器访问 H5：天然支持
- PWA：取决于系统浏览器和安装能力的支持情况
- App 包装：看所选跨端框架对鸿蒙的支持程度
- 原生鸿蒙 App：可能需要 ArkTS / HarmonyOS 工程，成本更高

所以第一版不把原生鸿蒙作为目标，只要求 H5 在鸿蒙手机浏览器里体验正常。

## 现在要预留的技术口子

App 化不是未来的事，现在的前端设计就要留口子：

- `/app` 页面按移动端优先设计
- 交互不依赖 PC hover
- 按钮触控区域足够大
- 后台路由和用户端路由分离
- API 层统一封装，便于 App 壳复用
- 登录态使用可迁移的 token 思路
- 样式适配安全区域

安全区域最容易漏：iPhone 底部横条、全面屏手势区会遮住底部 Tab 栏。处理方式是给底部栏加 `padding-bottom: env(safe-area-inset-bottom)`。

## 小结

回头看，跨端选型问题的答案不是"哪个框架最好"，而是"每一步是否值得"：

1. 业务没验证时，H5 的快速和低成本是最大的优势
2. PWA 用很低的额外成本换来安装感和弱网体验
3. Capacitor 让现有 Vue 代码直接变 App，不用重写
4. uni-app 和原生鸿蒙是选项，不是起点，等真实需求出现再评估

一个人项目的原则是：每一步都有可展示成果，不为可能用不到的多端提前买单。H5 跑通再升级 PWA，最后根据真实需求选择 Capacitor、uni-app 或原生鸿蒙方案。
